原始数值现在清楚了，整理如下：

**两侧 bpc 都在下降**（更大模型语言建模能力更强，对文本更不"惊讶"），但下降幅度不对称：

- 文言 bpc_lm_c：5.782 → 4.786，降幅 **17.2%**
- 白话 bpc_lm_v：2.759 → 2.172，降幅 **21.3%**

白话侧 bpc 降得更快，所以 density_gain（二者之比）反而升高。这正是 §6.10 Limitations 里描述的**记忆污染（memorization confound）**：

> GSM8K 是被引用最多的数学评测集，其中文版本极大概率出现在 4B/9B 的训练语料里。更大的模型见过更多语料（含 GSM8K），对这些**特定白话题目**的 bpc_lm_v 被系统性拉低；而 AI 生成的文言译文几乎不可能出现在任何训练集里，所以 bpc_lm_c 的下降只来自模型能力提升，速度慢得多。

**旧数据集（仿九章算术，AI 生成）之所以相反**：两端都是合成题，没有被记忆的可能。更大模型的训练数据里含有更多古籍/文言文，对古文 bpc 下降更多，白话侧没有特别的记忆加持，所以 density_gain 随模型变大略微下降——这才是"诚实"的规律，反映大模型古文建模能力更强。

**所以这不"正常"**，是数据集选择问题而非模型行为问题。用 GSM8K 做跨规模一致性验证，density_gain 随模型变大而升高，并不能解读为"更大模型验证了更高的文言密度"，而是大模型背了这套题。这也是报告建议下一步引入"LM 训练截止之后才出现的新写文言-白话平行语料"的原因。
