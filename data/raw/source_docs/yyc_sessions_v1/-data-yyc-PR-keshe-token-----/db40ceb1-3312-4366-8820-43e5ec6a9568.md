# 任务：在 tokenizer_compression_analysis.py 中加入多种主流信息密度指标（baseline 版）

## 项目上下文

我正在做一个研究项目，比较**文言文 vs 现代白话文**在 LLM tokenizer 下的
**信息密度（information density）**差异。最终目标是验证"文言文比白话文信息密度更高，
因此用文言文做 LLM 输入能节省 token"。

`tokenizer_compression_analysis.py` 是当前的分析脚本。它目前用一个**主指标**：
`bpc_lm = Qwen3.5-0.8B 对 text 做 teacher-forcing forward 得到的 bits-per-char`，
以及 `density_gain = bpc_lm(classical) / bpc_lm(vernacular)`。

**这个项目目前处于早期 baseline 阶段**。我希望保留当前脚本的所有数据加载、字体处理、
画图、报告生成、CLI 框架，**只在指标计算层做简洁扩展**，多增加几种主流学术指标
形成多角度对照，让它们**共同导向同一个结论：文言文信息密度更高**。

## 任务目标

在脚本中**新增 3 个并列的指标**，与现有的 `bpc_lm` 一起构成 4 个互补的信息密度
度量，最终在报告中横向对比，验证不同指标方向一致。

### 当前阶段的限定（重要，请严格遵守）

为保持 baseline 简单可控：

- ✅ **只用 1 种 tokenizer**：现有的 Qwen3.5-0.8B tokenizer，不引入其他 tokenizer
- ✅ **只用 1 种 LM**：现有的 Qwen3.5-0.8B，不引入外部 LM
- ❌ **不做** memorization probe / 跨 LM 对照 / 多 tokenizer 横评 ——这些留给未来扩展

## 要实现的 3 个新指标

### 指标 A: Compression bits-per-character（Cilibrasi & Vitányi 2005）

- **论文**: Cilibrasi & Vitányi, "Clustering by Compression," IEEE TIT 51(4):1523–1545, 2005.
- **直觉含义**: 用通用压缩器（gzip/bzip2）测量"每个字符所携带的信息量"。
  压缩后字节数越多 → 文本越不冗余 → 信息密度越高。
- **公式**: 
  - `bpc_compress(x, C) = 8 * |C(x)| / n_chars(x)`，其中 C 为压缩器
  - `density_gain_compress = bpc_compress(classical) / bpc_compress(vernacular)`
  - **结果 > 1 表示文言每字信息密度更高**（与现有 density_gain 方向一致）
- **要求**: 用 2 种压缩器分别计算并并列展示：
  1. `gzip`（Python 标准库 `gzip`，compresslevel=9）
  2. `bz2`（Python 标准库 `bz2`，compresslevel=9）
- **短文本修正（必须实现）**: gzip header 约 10-30 bytes，对 15 字的短文本会
  严重高估 bpc。实现 **preamble 协议**：在压缩目标文本前拼接一段固定的预热文本
  （约 5000-8000 字现代白话），用差分得到目标文本的"边际压缩长度"，摊薄 header
  开销：

  在脚本顶部新增一个常量 `PREAMBLE_TEXT`（约 5000-8000 字的现代白话文本，
  你可以自己生成一段连贯的现代散文/科普/新闻风格文本，或拼接多段）。
  注意：preamble 文本本身应该是**中性现代白话**，不要混入文言或专业术语，
  以免污染压缩字典。
- **优势**: 完全无 LM，无 tokenizer 依赖，纯文本属性。
- **劣势（必须在 report 中提及）**: 不能区分"信息密度高"与"译文冗余"。

### 指标 B: Tokenizer Token Ratio（Petrov 2023 简化版）

- **论文**: Petrov, La Malfa, Torr & Bibi, "Language Model Tokenizers Introduce 
  Unfairness Between Languages," NeurIPS 2023 (arXiv 2305.15425).
- **直觉含义**: 同一段意思，用文言文和白话文分别让 tokenizer 切分，比较 token 数。
  白话需要的 token 更多 → 文言更"省 token" → 在固定 context window 下文言能
  装下更多信息。这是**与 LLM 实际部署最直接相关**的指标。
- **公式**: 
  - `token_count_ratio = n_tokens(vernacular) / n_tokens(classical)`
  - **结果 > 1 表示白话需要更多 token 才能表达同样内容，即文言更密**
- **重要说明**: 脚本里已经有 `token_ratio = n_tokens_v / n_tokens_c` 这个字段
  （在 `compute_pair_metrics` 里）。**你不需要重新计算它**，只需要：
  1. 在报告和图表中**把它从"长度层附属指标"提升为"4 大主指标之一"**，
     与 density_gain 等并列展示
  2. 显式标注它的论文出处（Petrov 2023）和直觉含义
  3. 在结论汇总中纳入这个指标的方向判断
- **优势**: 完全无记忆污染，直接对应 LLM token 预算。
- **劣势**: tokenizer 自身对文言/白话的训练曝光度不同，会引入轻微 bias
  （但本 baseline 阶段不展开讨论，留给 limitations 一句话即可）。

### 指标 C: Character Unigram Entropy with Miller-Madow Correction（Bentz 2017）

- **论文**: Bentz, Alikaniotis, Cysouw & Ferrer-i-Cancho, "The Entropy of Words—
  Learnability and Expressivity across More than 1000 Languages," Entropy 19(6):275, 2017.
  Bias correction: Miller, "Note on the bias of information estimates," 1955.
- **直觉含义**: 直接对文本中"字符出现频率分布"算 Shannon 熵。如果一段文本里
  字符分布更"均匀分散"（罕用字多、重复少），单字符熵越高 → 每字承载的不确定性
  越大 → 信息密度越高。Miller-Madow 校正修正了短样本下 MLE 熵估计的下偏。
- **公式**: 
  - 字符 MLE 熵: `H_1 = -Σ_k p_k * log2(p_k)`，其中 `p_k = c_k / N`
  - Miller-Madow 校正: `H_MM = H_1 + (K - 1) / (2 * N * ln(2))`
    其中 K = 该文本中观察到的不同字符数，N = 总字符数
  - `density_gain_entropy = H_MM(classical) / H_MM(vernacular)`
  - **结果 > 1 表示文言每字熵更高，信息密度更高**
- **重要警告与处理**:
  - Bentz 2017 指出 character entropy 需 >1k 字才收敛。我们的单条文本通常远低于此。
  - **处理策略**: 
    1. 单对粒度仍计算 H_MM，但**仅用于趋势观察**，不作单条强结论
    2. **额外做 category 聚合**：把每个类别下所有文本拼起来再算一次 H_MM，
       作为更稳健的统计（聚合后字数过千，更接近收敛区间）
    3. 在 report 中明确说明这个限制
- **优势**: 完全无 LM，无 tokenizer 依赖，纯文本属性，与指标 A 互为补充
  （A 是基于通用压缩器，C 是基于字符频率统计）。
- **劣势**: 短文本不可靠；不捕捉长程依赖；只看一阶频率。

### 现有指标 D: bpc_lm via Qwen3.5-0.8B（保留）

- **直觉含义**: 让一个语言模型对文本做 teacher-forcing，看它"惊讶程度"，
  归一化到每字符的 bits。模型越惊讶 → 文本越难预测 → 信息密度越高。
- **现有 `density_gain = bpc_lm_c / bpc_lm_v` 字段保留不动**
- 在主指标对比中作为第 4 个并列指标展示

要让 SDE(文言) > SDE(白话)（density_gain_sde > 1），文言端需要在每个分量都"赢"：

- `1 − R` 文言 > 白话，等价于 **R(文言) < R(白话)**（冗余更少）
