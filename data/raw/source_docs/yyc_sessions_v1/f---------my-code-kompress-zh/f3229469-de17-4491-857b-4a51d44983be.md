## 各脚本详解

### 1. `build_dataset.py` — 两个子命令

**`source-pool` 子命令**：把 `.md`/`.txt` 文件目录切成 200~800 字的中文段落候选池。

关键逻辑（[build_dataset.py:84-127](scripts/build_dataset.py#L84-L127)）：
- `paragraphize()`：剥掉代码块/HTML注释，按空行分段

**`training` 子命令**：把标注好的 labeled pairs 展开成训练 JSONL（自动按 8:1:1 hash 分 split）。

split 分配逻辑（[build_dataset.py:214-221](scripts/build_dataset.py#L214-L221)）：基于 `sample_id` 的 MD5 hash，末位 mod 10：`0-7=train, 8=val, 9=test`，确保同一 id 每次分配结果稳定。

### 2. `label_with_deepseek.py` — teacher 标注

- 每条样本调用一次 DeepSeek API，返回 JSON：`{compressed_text, style_tag, contains_anchor, quality_notes}`

### 3. `build_review_queue.py` — P0/P1/P2 风险分层

                continue

        ts = format_timestamp(entry.get("timestamp", ""))

            content = msg.get("content", [])
            text = extract_text(content)
            if text:

        elif etype == "assistant":

            content = msg.get("content", [])
            text = extract_text(content)
            if text:

**真正会被去重跳过的情况**：用户完全重复发出同一批消息、claude 给出完全相同的回复，这种情况下两个 session 提取出的 segments 内容完全一致，才会触发 `duplicate`。

**"共享前缀"问题**（当前未处理）：前 N 段完全一样，只有末尾几段不同。这类 session 对 source pool 来说其实**不是纯浪费**——前缀段的重叠在 source pool 里会产生内容相同的候选片段，会在 `build_dataset.py source-pool` 阶段因 `sample_id` 不同而都进入池里，但 DeepSeek 标注出来的 labeled pair 会完全相同。

要防这一层，需要在 `source pool` 阶段做去重，而不是在导出阶段。这是下游应该处理的问题，我在 `build_dataset.py` 那里加一个选项更合适。
