### 方案 A：纯 Python 一条流水线（推荐，最轻量）

- **页数过滤**：docx 不直接存"渲染后页数"，两种取数方式：
  - 读 `docProps/app.xml` 里的 `<Pages>` 字段（Word 保存时写入，**速度最快**，但部分 WPS/老文件可能没有或失真）；
  - 兜底用 `python-docx` 统计字符数（如 < 一定阈值视为短文），或对没有 `<Pages>` 的少数文件再做 B 里的 LibreOffice 转换。
- **去图**：docx 本质是 zip，把 `word/media/` 全部删掉，再清理 `document.xml` / `*.xml.rels` 中的 `<w:drawing>`、`<w:pict>`、`Relationship Type=".../image"`，重新打包即可。比用 python-docx API 更彻底（能去掉页眉页脚里的图、SmartArt 等）。
- **脱敏**：先用正则覆盖结构化信息（手机号 `1[3-9]\d{9}`、身份证 18 位、邮箱、银行卡、统一社会信用代码、座机、地址中的门牌号、URL/IP），再用中文 NER（如 `hanlp` 或 `paddlenlp`）处理人名/机构名。直接 `re.sub` 替换为 `[REDACTED]` 或 `***`。

**优点**：单机批处理 2000+ 文件可控；**缺点**：`<Pages>` 字段对部分文件不可信，正则脱敏对非结构化人名/地址覆盖有限。

---

### 方案 B：LibreOffice + Python（准确度更高）

- 用 `soffice --headless --convert-to pdf` 把 docx 全部转 PDF，用 `pypdf` 数页数 → **页数判断 100% 准确**；
- 对页数 ≥ 10 的原 docx 再走方案 A 的去图 + 脱敏。
- **代价**：2000 份转 PDF 大约几十分钟到 1–2 小时，看机器。

如果你担心 `<Pages>` 字段不可靠，建议至少对"边界文件（5–15 页）"用这条路径校验。

### 第 1 步：先把它从 shell 的"挂断列表"里摘掉（必做）

在跑脚本的那个终端里：

`disown -h` 之后，SSH 断了 **不会** 给它发 SIGHUP，进程本身不会被信号杀。
