主要有这些路径，按"保真度 / 成本 / 是否适合 9 万 + 批量"排个序：

## 1. LibreOffice headless（推荐起步）
免费、Linux 可用、命令行可脚本化。文本/段落/表格保真度 OK，复杂排版（嵌入对象、艺术字、域代码）可能有偏差。

- 9 万文件单线程约 50+ 小时；并行 8 路 ≈ 6–8 小时
- 失败/超时建议加 timeout 包一层
- 中文字体缺失会引起版式漂移，提前装 `fonts-wqy-microhei fonts-noto-cjk`

## 2. WPS Office for Linux（中文文档保真更好）
WPS 对国产 doc/wps 兼容性常优于 LibreOffice，CLI 类似：

- 需要从官网下载 `.deb/.rpm` 安装，闭源但免费
- 适合先用 LibreOffice 跑一遍，对失败/异常文件再用 WPS 补救

## 3. Aspose.Words（商业 SDK，最高保真）
Python / Java / .NET 都有，对复杂样式、公式、域、目录、批注还原最完整。

- 缺点：商业授权（按文件数/年订阅），大批量需算账
- 优点：纯本地、没有云上传隐私问题

## 4. Microsoft Word 自动化（金标准但需 Windows）
Word + VBA / PowerShell / pywin32 调 COM，转出来基本等同人工"另存为"。

- 保真度最高
- 必须 Windows + Word；91K 文件需要写脚本控制崩溃/超时
- 跨平台麻烦，不适合 Linux 服务器场景

## 5. 云端 API（CloudConvert / Aspose Cloud / Zamzar）
保真度好，省运维，但 ——
- 9 万 × ~$0.01–0.05 = 上千到几千美元
- **隐私敏感**：标书含真实企业信息，上传外网服务存在合规风险，不建议

## 6. 不推荐
- **Pandoc**：只读 .docx，不读老 .doc，不适用
- **abiword --to**：年久失修，复杂 doc 失败率高
- **antiword / catdoc**：只提取文本，不保留排版，等同丢信息
