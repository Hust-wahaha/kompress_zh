我们要测试并开源一个 Claude/Codex Skill，叫 exam-cram-kit（仓库名计划用 cram-kit）。

【这个 skill 是什么】
帮大学生把课程课件（PPT/PDF/Word 讲义）一章一章地整理成考前速成资料。交付物：
1. 重点提要.md —— 分级知识点（🔴必考核心/🟡重点掌握/🟢辅助理解），只留重点、砍掉废话
2. 思维导图 —— Markmap 格式 .md（主）+ Mermaid 预览块
3. 公式速查.md —— 按章节，含符号说明和"何时用"（无公式则不生成）
4. 易错与必背.md —— 易混对比 + 必背定义
5. 范围内答疑 —— 只用课件内容，超纲用【超纲补充】标注，完全超范围则明确提示不瞎编
6.（可选）Anki 卡片 / 预测考题 / 一页速查表

【已锁定的设计决策，请勿推翻，只做实现层优化】
- 输出语言跟随课件原文，不翻译
- 工作流是"逐章节"迭代：建立课程→逐章发课件→生成→确认→下一章，内容累积进同一套文件
- 可选输入"老师的复习题PDF"：作为最强考试信号，反推对应知识点升级为🔴，打🎯标记；信号优先级 复习题 > 老师强调 > 内容判断
- 三类"学习文档"(1/3/4)支持图示批注：依赖图表的点不强行用文字描述，改打 📎 配合PPT第X页图示
- 母版是 Markdown，导出可批注PDF两条路：有代码环境→pandoc/weasyprint直接生成；无代码→用 assets/print.html 浏览器打印存PDF（宽批注边距、KaTeX渲染公式、章节分页）

## 第一档：必须改的 skill 问题（影响输出正确性）

**1. SKILL.md 第 85-97 行的 Python 库依赖描述错误**
- 现状写"in a code environment use python-pptx, pdfplumber/pymupdf, python-docx"。
- 真实问题：Claude 4.x / Codex 都原生多模态，宿主把 PDF/PPT 直接喂给模型；让模型主动调库等于让它**绕开自己的视觉能力**，反而丢失图表里的视觉信息（如电压传输特性 5 段曲线）。
- 建议改成："默认假设文件内容（含图）已在上下文里。仅当宿主只提供文件路径而非内容时，再用代码读取。" 

**2. 复习题 PDF 里包含"学生手写答案"的场景没规则**
- 这次的 [第6讲复习题.pdf](example/第6讲复习题.pdf) 后 5 页是学生扫描的手写答案，OCR 出来一堆乱码（"煮算䲜讖霍䨊"之类）。
- 当前 [grading-and-curation.md](grading-and-curation.md) 把复习题 PDF 当成"老师发的题目"对待，没说明：① 答案是否参考；② 乱码该怎么处理。
- 建议：在 grading-and-curation.md 加一段"如果复习题 PDF 里夹带学生笔迹/手写答案：只用题目部分反推知识点，手写答案不作为权威来源（学生可能写错）；若 OCR 严重失败，明确告诉学生只用了题目"。

**3. 课件里"几乎完全不考的整章"的处理规则模糊**
- 本次 TTL 部分（11 页 / 占课件 17%）复习题 0 命中，按规则我直接整章压缩到 🟢。这是对的，但 SKILL.md / grading 里没说"整大块零命中"该激进还是保守。
- 建议：在 grading-and-curation.md 的"Discard"列表后加一条 **"整章/整大块零命中复习题、且老师无强调 → 默认压缩到 🟢 一两句话；不要因为占了课件 1/3 篇幅就保留 🟡。"** —— 这是"丢弃 > 摘录"价值观的关键体现。

**4. "易考形式"维度的标签是隐性的**
- 复习题给了非常明确的"画图题"、"分析写表达式题"、"列真值表题"信号。我在 outline 里有标"易考形式：分析题"，但 [templates.md](templates.md) 只在模板第 30 行示例里轻描淡写提了一下，没作为必填字段强调。
- 建议：把"易考形式"作为 🔴 项的**必填字段**写进模板（🔴 必填，🟡 可选，🟢 不要）。这是学生最值钱的信息——"我知道这是重点，但我要怎么练？"

## 第二档：影响产出质量但不致命的问题

**5. Mermaid 块在 markmap 文件里的位置冲突**
- 我的 [思维导图.md](example/output/思维导图.md) 把 mermaid 块也塞进了 markmap 文件。但 markmap 解析时会把 mermaid 块当成普通代码块（无害），而当用户直接预览这份 .md 时反而会看到两份导图。
- 建议：templates.md 应明确说 mermaid 块**单独输出在对话里作为预览**，不写入 思维导图.md 文件中——文件里只放 markmap 内容。

**6. 公式速查表的"何时用"列在所有公式都给出后才显得有价值，单行表格易塞挤**
- 实测 OD 门 Rp 上下限两行的"符号说明"超长，表格在窄屏会很难读。
- 建议：templates.md 给出降级方案——超过 4 个符号时改用"公式 + 项目符号符号说明"的卡片式布局而非表格。

**7. 📎 标记数量爆炸**
- 这一章纯电路图，我打了 30+ 个 📎。对学生来说，每条都跳页等于没跳。
- 建议：grading-and-curation.md 增加 **"📎 收敛规则"**：同一 PPT 页只标 1 次；连续多个知识点指向同图时只在主条目上标。

**8. 没产出"易考形式：分析题"练习路径**
- 复习题第 12-15 题是分析题，但我没法直接生成"分析题练习"——这是 skill 的可选交付物 5 (Anki) 或 6 (预测题) 该接住的，但默认没生成。
- 建议：当复习题信号里有"画电路"或"写表达式"占比超 1/4 时，**默认提示**学生要不要要预测题；当前 SKILL.md 把它放在 optional add-ons，没说什么时候主动触发。
