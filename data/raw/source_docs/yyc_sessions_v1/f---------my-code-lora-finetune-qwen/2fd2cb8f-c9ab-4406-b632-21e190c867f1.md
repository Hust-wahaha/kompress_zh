我已经把 5 个指标的实现链都翻了一遍，先给出严格 review，再改 markdown 渲染。

## 一、5 个指标的计算逻辑严格 review

### 1. `cot_completeness_rate`（推理过程完整率）
**实现**：[src/common/style_detect.py](src/common/style_detect.py) 的 `is_cot_complete`

- **算什么**：每条样本判 0/1，整批求平均。
- **判定要点**：必须同时出现 `<think>` 和 `</think>`，且开 tag 在闭 tag 之前。`open_idx >= 0` 防住"只输出 `</think>`"导致 `close_idx > -1` 误判的边界。
- **已知妥协**：只看首个匹配对，不校验配对数；模型输出多个 `<think>` 不会判错，但也不会发现异常。在课设这种单题面场景里足够。

### 2. `generation_completion_rate`（整体回答完整率）
**实现**：`is_generation_complete`

- **算什么**：在 CoT 完整的前提下，进一步要求出现「答案」二字、且整段以中文句号结尾——亦即未被 `max_tokens` 截断。
- **三个条件递进**：缺 `</think>` → CoT 不完整；有 `</think>` 但没"答案：" → 推理写完但没给结论；前两个都过但末尾不是「。」 → 答案串还在生成中被截了。
- **小风险**：`'答案' in text` 子串匹配——若模型在 CoT 里夹了"答案是 X"也会算数。低概率，未做更严的"必须在 `</think>` 之后"判定，保留为可改进点。

### 3. `answer_accuracy`（答案准确率）
**实现**：[scripts/eval_five_metrics.py:104-115](scripts/eval_five_metrics.py#L104) `extract_answer`，4 级回退 + 字符串相等

回退顺序：① `答案[：: ]*N` → ② `故…=N` → ③ 末行 `=N` → ④ 全文最后一个不与字母相邻的数字。抽到的串与 `gold_answer` **字符串严格相等**。

- **与 `eval_compare_full.py` 同口径**：刻意复制而非抽公共，免得两条评测线漂移。
- **已知妥协**：不做数值规整。`"15"` ≠ `"15.0"` ≠ `"1,500"`。s800_think 的 gold 全是纯整数字串，不会踩；新增数据集需保持这个口径。
- **截断耦合**：当 `max_tokens` 很小时 ①②③ 全部 miss，④ 兜底常抽到题面或 CoT 中间数字，准确率因此被压低。配合 `cot_completeness_rate` 一起看才能判断"是真错还是被截"。

### 4. `cot_quality_score`（推理质量评分，可选）
**实现**：[scripts/eval_five_metrics.py:398-449](scripts/eval_five_metrics.py#L398) `apply_cot_quality`

- **采样**：`mode='cot_quality'` 时**只复核 `cot_complete == True` 的样本**（避免给"空 CoT"白白送钱）；`mode='all'` 则全量。
- **打分**：每条独立调用一次 DeepSeek V4 Flash，强 JSON 返回 `{"score":1-5, "reason":...}`，超 1-5 直接抛 `ValueError`。
- **聚合**：`mean = sum(scores)/len(scores)`，只对**被复核样本**取均值。
- **解读告警**：极小窗口下 `cot_complete` 比例低 → `reviewed_cases` 也小 → `mean` 是"幸存者均分"，不能直接和大窗口比。读这一列时**必须并看 `reviewed_cases` 与 `cot_completeness_rate`**。
- **成本闸**：`--llm-review-max-cases` 上限。

### 5. `style_faithfulness`（推理风格忠实度，4 个子指标）

**关键细节**：
- `style_label` 在 [src/common/style_detect.py](src/common/style_detect.py)：`m=0 且 c=0 → unknown`；`m>0 且 c>0 且 |m-c|≤1 → mixed`；否则取较多的一侧。
- 空 CoT / 被截 CoT → `style_label='unknown'` → **不可能等于 modern/classical** → 风格忠实度被记为 0。这是有意为之：CoT 都没写完就不该给风格分。
- **baseline 例外**：`expected_style='none'` 时 `faithfulness_rate` 设为 `None`，`by_view` 同样设为 `None`，markdown 显示 `-`。
- 词表 self-check：80 条 gold CoT 上 modern 40/40、classical 40/40、零混淆、零英文漏出。

### `by_view` 拆分
对每条样本同步累加到 `modern` / `classical` 两个桶。每个桶里 5 个指标按桶内 total 归一，没有 `style_faithfulness` 子结构，而是直接出 `style_faithfulness_rate` 一个标量。

你的观察是对的，**在 `temperature=0`（即贪心解码）下，两种做法等价**。原因是自回归生成的每个 token 仅取决于前序 token，与 max_tokens 上限无关：max_tokens 只控制何时停止，不影响已生成 token 的 logits 计算。因此 max_tokens=512 跑出来的前 64 个 token，和 max_tokens=64 单独跑出来的 64 个 token **完全相同**。

脚本默认就是 `temperature=0.0`（见第 200 行），所以这个等价确实成立。

---

**但有一个细节值得注意：**

"截断"必须在 **token 边界**上截，而不是字符边界。当前脚本每次推理保存的 `response` 是 N 个 token 解码出的字符串。如果你只取长输出的前 K 个字符来近似"max_tokens=K/avg_chars_per_token"，字符数和 token 数之间有漂移（中文 token 通常对应 1–3 个字符）。想做精确等价，要么：

1. 保存完整输出后重新 tokenize、在 token N 处截断、再 decode，然后算指标
2. 或者接受"约等于"——对这里的字符串匹配指标（`</think>`、`答案：N`）而言，截断误差通常在 ±几个字符以内，不会改变指标结论

---

**为什么脚本现在选择了"多次推理"这种低效做法：**

简单——不需要处理 tokenization，直接拿 `response.choices[0].message.content` 就是"这个窗口下模型真实交付的字符串"，无需额外处理。代价是 M 个 max_tokens 档位就要推 M 次，实际上有 (M-1)/M 的计算是冗余的。

对课设规模（80 条测试集、5 个档位）影响不大；如果要做大规模 benchmark 扫描，值得改成"推一次最大窗口 + token 级截断重算"的方式。
