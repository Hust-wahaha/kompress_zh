## 三、可信的结论

### ✅ 结论1：LoRA 能稳定控制 `<think>` 语言风格

**可信度：高。** 定性证据充分：baseline 输出英文 `Thinking Process:`，微调后白话题输出白话中文 think，文言题输出文言中文 think。这是该项目最核心且最可复现的发现，不依赖任何评测指标的口径选择。

### ✅ 结论2：CoT 风格对准确率影响显著，排序稳定

**可信度：高。** 在多个独立评测 run 中一致：

> **structured** (m2s/c2s) > **modern** (m2m/c2m) > **classical** (m2c/c2c)

原因合理：structured 格式（逐行列式计算）最紧凑，相同 max_tokens 下 CoT 完整率最高，从而答案出现率最高。

### ✅ 结论3：白话题面优于文言题面（跨模型一致）

**可信度：高。** 所有 6 个微调模型中，modern view 准确率始终高于 classical view（差距约 10–20%）。直接原因：基座模型预训练语料中白话现代汉语远多于文言文。

### ✅ 结论4：微调显著改善输出格式纪律

**可信度：高。** 微调模型在 max_tokens=160 时，generation_completion_rate 达 94–97%（即能稳定输出"答案：N。"格式），而未微调 baseline 在 160 token 内无法规范格式。这说明 LoRA 在格式控制层面有效，与数学能力无关。

## 四、有问题的结论

### ❌ 问题1：s800 的"100% 准确率"不具数学能力意义

**严重程度：高。**

s800 数据集只有 6 种四则运算题型（give_away / box_total / equal_division 等），模板化程度极高。测试集与训练集**同分布**（均由同一 `generate_dataset.py` 生成）。

关键证据：eval_compare_full.py 中，baseline 经 LLM 复核后同样达到 **100%**。这意味着基座模型本身就已经会做这些简单题，微调只是改善了输出格式，而非数学推理能力。

> 结论应修正为：**s800 微调提升的是输出控制能力，不是数学能力。**

### ❌ 问题2：eval_five_metrics 中的 baseline 比较全部无效

**严重程度：高。** 在 gsm1k 6models 等所有 eval_five_metrics 评测中，baseline 在 max_tokens=32–160 下的准确率均为 0%，导致图表中"baseline=0"是一条无意义的参考线。

根因已确认（三个证据相互印证）：

1. **Qwen3.5-0.8B 官方 model card 明确警告**："在思考模式下，该模型比其他 Qwen3.5 模型更容易陷入思维循环（thinking loops）"
2. **20260605 Upper_Limit 实验**（thinking=ON, max_tokens=2048）：baseline 准确率依然为 0%，cot_completeness_rate 仅 0.4%（2048 个 token 全部被无限循环的 think 消耗）
3. **20260606 Unthinking 实验**（thinking=OFF, max_tokens=2048）：baseline 准确率 38.9%，证明模型本身有能力

`eval_five_metrics.py` 的代码逻辑（`enable_thinking_for(None) = False`）理论上已关闭 baseline 的 thinking 模式，但 max_tokens=160 对于非思考模式下完成一道 GSM-1K 题目外加"答案：N。"格式仍然不够。

### ❌ 问题3：微调是否真正提升 GSM-1K 准确率，目前无法断言

**严重程度：中。** 

当前最强微调模型 c2s 在 max_tokens=160 时达到 **37.9%**，baseline（non-thinking, max_tokens=2048）为 **38.9%**。差距仅 1%，且微调模型的准确率在 160 token 处**仍未饱和**（cot_completeness_rate=95.2%，说明还有 5% 样本被截断）。

若给微调模型同等的 token 预算（如 512 token），其准确率大概率会高于当前数值。但目前没有这个对照实验。

此外还有一个训练侧的隐患：**max_length=512 导致训练目标被截断**。典型 gsm1k 样本的完整 `<think>CoT</think>答案：N。` 序列经常超过 512 token，意味着模型在训练时看到的是截断的 CoT，这会损害推理质量。

### ❌ 问题4：s800 评测与 eval_five_metrics 评测结果不可直接比较

**严重程度：中。** 两套评测工具的答案抽取逻辑、baseline 的 thinking 设置、max_tokens 设置均不同：

这是 s800 baseline 在 eval_compare_full 里有 55%，在 eval_five_metrics 里有 0% 的原因。

## 七、一句话总结

**可信结论（格式控制层面）**：LoRA 微调成功地将思维风格从英文切换为中文（白话/文言），并使输出格式高度规范；structured CoT 风格比 natural language CoT 效率更高。

**存疑结论（数学能力层面）**：当前数据无法证明微调提升了 GSM-1K 数学准确率——最好的微调模型（37.9%）与未微调基线（38.9%）几乎持平，且比较条件不统一（token 预算差了 10 倍）。这不代表微调无效，只代表目前的实验设计不足以得出该结论。
