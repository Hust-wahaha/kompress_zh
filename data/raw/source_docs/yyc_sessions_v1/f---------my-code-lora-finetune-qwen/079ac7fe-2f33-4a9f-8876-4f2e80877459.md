## 结论：不是 bug，是 mt=16 太短 + extractor 末位回退造成的统计噪声

### 直接证据

在 [predictions/m2m_mt16.json](runs/20260521_112232_eval_s800_think_qwen3.5-0.8b_m2m_vs_c2m_mixed_small/predictions/m2m_mt16.json) 和 c2m_mt16.json 上点对点核对 80 条样本：

- **mt=16 下没有任何样本生成出 `答案：N`**：summary 里 `推理过程完整率=0%`、`整体回答完整率=0%`，输出只有 `<think>` 开头几个汉字就被截断。
- **m2m 总命中 = 3 白话 + 4 文言 = 7；c2m 总命中 = 4 白话 + 3 文言 = 7**。两边一共就差 1 条样本落在不同的 view 桶里。
- m2m 和 c2m 在 80 题里有 **33 题输出完全一致**、47 题有差异。差异都是词汇级（"盒"↔"匣"、"送给小明"↔"和"），并不是答案数字的差异。

### 7/80 这个分数从哪儿来的

[scripts/eval_five_metrics.py:172-183](scripts/eval_five_metrics.py#L172-L183) 的 `extract_answer` 三条主正则（`答案：N` / `故…=N` / 行尾 `=N`）在 mt=16 全部失配，**回退到 "text 里最后一个数字"**。看实际 m2m_mt16 的响应：

被截到这里时，"最后一个数字" 是题面被复述出来的最后一个操作数（如 `11`），偶尔正好等于 gold（部分 give/box 题答案就是其中一个操作数附近的数）。80 题里凑巧命中 7 条，**和模型推理能力无关**。

m2m 和 c2m 因为用词差异，会把题面操作数复述到 16 token 窗口里的位置稍微挪一两个字，于是同一题在两个模型里"被截断时最后一个数字是谁"会换；这种位移在两个 view 之间各搬走一条，就成了 `7.5%↔10%` 的镜像。

### 直接对账

两条关键观察：

1. **"推理风格忠实率" 在 mt=24 严格等于 "推理过程完整率"**。所有 `closed && label!=modern` 的桶都是 0：只要 `</think>` 闭合上了，CoT 关键词就 100% 命中 `modern`；没闭合的 CoT 一律 `style_label='unknown'`，不被计入忠实。

我对账了训练数据和测试数据的实际内容，找到几个**数据/任务设计层面**的根本原因。

## 关键发现：两个 adapter 的监督目标完全相同

对照同一个 `base_id=give-009` 在 [train_s800_m2m.jsonl](data/pairings/train_s800_m2m.jsonl) 和 [train_s800_c2m.jsonl](data/pairings/train_s800_c2m.jsonl) 里的样本：

**assistant 目标逐字相同**。两个 adapter 真正的差异只有"input 怎么映射到一个相同的输出"。LoRA 输出端学到的分布是同一个，cross-view 测试时两个 adapter 收敛到等价行为是几何必然的，不是训练失误。

## 数据集层面的具体成因（按影响排序）

### 1. c2m 是"半边对照"，不是真对照（最大成因）

- 任务里"文言效应"应当体现在**输入 + 输出**整套语言风格上。当前 c2m 只在输入侧拿了文言，输出侧仍然是白话 CoT。
- 数据生成器其实已经预留了 `classical_think` 字段，[data/pairings/](data/pairings/) 里也存在 `train_s800_c2c.jsonl`（文言→文言 CoT）。当前选 c2m 等于主动 collapse 掉了输出端的语言风格信号。
- **改法**：把 c2m 换成 c2c（文言输入 → `classical_think` 监督），m2m 保持不变，这才是严格的"语言风格对照"。

### 2. 文言/白话在数据里只是浅层词汇替换

实际看 6 个 family 的配对样本：

- **平均字符重叠率 = 0.545**（两套题面一半字符是同一个）
- **数字部分（阿拉伯数字 + 量词）几乎不变**：26/11/8/3/25/5/1千克/500克
- 模型只要建立 ~10 对一对一替换（匣=盒、遗=送、尚余=还剩、几何=多少…），就把所有 classical 题"反向编译"成 modern 模板。这个学习量级很小，s800 + r=8 LoRA 训 2 epoch 完全够。

### 3. 数学信息是 language-agnostic

- 阿拉伯数字 "26" "11" "5" 在文言和白话里都直接保留。
- 模型只要正则式抓数字 + 识别 family 模板 = 拿到全部解题信息。
- 文言/白话的语言理解**从一开始就不是这个数据集的瓶颈**，所以再怎么压缩 max_new_tokens 也压不出语言层面的差异，只压出"CoT 写没写完"的差异。

### 4. 题面太短、运算单步

- 白话题面均长 **20 字符**，文言题面均长 **17 字符**；都是 1-step 加减乘除。
- 课设要求的"高压缩比下测 CoT 完整性"假设：语言理解占用一部分 token 预算。但当前题面短到 24 个 new tokens 就能写完整个 `<think>`，**语言风格根本占用不了多少 token 差**。

### 5. family 只有 6 种，模板化严重

- give_away / box_total / equal_division / unit_price / bundle_count / weight_remaining
- 每个 family 训练侧 ~50 条，schema 固定（"X 有 N，Y 掉 M，问几"），模型在 2 epoch 后实际上是在背 6 个模板，文言/白话变体被吸收为模板内部的"同义词噪声"。

### 6. base_id 跨 view 共享 → 答案分布被两边都"灌"过

- 测试集严格按 base_id 切分（test 80 = 40 个 base_id × 2 view），训练集/测试集之间没有泄漏。
- 但因为 c2m 的 assistant target = modern_think，**同一个 base_id 的 modern_think 在 m2m 训练时见过、在 c2m 训练时也见过**。模型对"这类题该输出什么 think"的记忆来自两边，cross-view 测试自然没区别。这不是泄漏，是设计耦合。

## 想真正放大文言-白话效应，按性价比排序

最具课设性价比的是 **A + B**：A 几乎零代价（数据已有），B 是数据生成器一次性升级。如果论文/报告只想呈现"高压缩比下 CoT 完整性差异"，A 落地后 mt=24 那档应该能看到 m2m 文言 22.5% 风格忠实率 → c2c 文言 60%+ 这种数量级的真实分化（c2c 训练时 classical_think 平均更短 / 词汇更紧凑，闭合更快，且风格判定与输入对齐）。

**简言之**：当前看不出文言效应，**根因不在评测协议、不在模型、也不在训练设置，而在数据集设计**——任务被你设计成了"两种近义白话变体 → 同一个白话 CoT"，所以无论你压不压缩、用什么指标，都看不到本质差异。

## 找到 bug 了：是评测脚本的正则错抓"截断中的答案"

m2m mt40→mt44 退化的 10 条，**全部是同一个机制**。直接看一例（gram-019-modern, gold=3700）：

文言侧更狠：文言 think 用了"尚余""食去"等字符，留给"答案"段的 token 更少，3700 被截成 **37**（少两位）。

**c2c mt24→mt28 的 11 个 regression 也是同一个机制**：mt=24 时 think 闭合但"答案：" 还没写出，正则 2 (`故…=N`) 或 fallback 抓 think 里的正确数字；mt=28 时多 4 个 token 刚好够写"答案：1"（gold=15 / 35 / 120 / 110 等，第一个数字位之后就被截）→ 正则 1 抓到 1 / 1 / 1 / 1。

证据汇总：
- m2m mt40 vs mt44：80 条里 **68 条 response 逐字相同**（贪心解码前缀不变），剩下 12 条只是 mt=44 多生成了几个 token；模型本身没退化。
- m2m mt40→mt44 的 10 个 regression **全是 `gram_` family**（答案是 3-4 位数 2600-3700），其他 family 答案 ≤2 位数，4 个 token 足够写完整 "答案：N。"，不触发 bug。
- c2c mt24→mt28 的 11 个 regression 用的都是正则 1 抓到了 "1" / "1" / "1" 这种第一位数字。
- c2c mt36 vs mt40：80/80 逐字相同、80/80 正确 —— token 够用之后稳定，进一步佐证不是模型在"想多了"。

## c2c / m2m 的 CoT 长度分布（在 mt=44 完整完成时观测）

关键观察：**两个模型在自己 in-distribution 的 view 上都更紧凑，但在 off-distribution 的 view 上分布更分散（有更长的尾巴，也有偶尔的"偷懒"短样本）**。c2c 看到 modern 输入会复制题面里的"送给小红"这种长名词，导致 CoT 长度方差变大；同样地 m2m 看到 classical 输入会做一次再表述。

## 4 个问题逐条解释

### 1. mt=28 c2c 白话占优（60% vs 47.5%）

mt=28 时所有样本 `</think>` 都闭合了（40/40），分歧只在"`答案：N。`是否完整写出"。

实际未完成的样本长这样：

也就是 mt=28 是个**"几乎够、但句号刚被截掉"**的窗口。能跨过 28 token 写出"。"的，是 CoT 短的那批样本。c2c 在 modern 输入下的 CoT 长度**双峰**（有"复制送给小红"的长样本 + 有"直接故 N-M=X"的偷懒短样本），偷懒短样本能写出"。"的比例更高 → modern 24/40 vs classical 19/40。

差 5 条，对应表里的 60% vs 47.5%。

### 2. mt=32 c2c 文言占优（85% vs 87.5%）

token 预算扩大 4 之后，**c2c classical 那批集中分布在 22-26 字符的样本几乎全过线**，而 modern 长尾里那些"复制了送给小红"的长样本仍然差几个 token。结果 classical 反超：modern 34/40，classical 35/40。

差 1 条，就是边界处分布形状反转的体现。**到 mt=36 两边都满 100%**，差距消失。

### 3. mt=44 m2m 白话占优（87.5% vs 85%）

同样机制，**m2m 镜像 c2c**：m2m 训练目标是 modern_think，在 modern 输入上 in-distribution，CoT 用"还剩""所以"这些"顺手"词；在 classical 输入上要做"食去→吃掉"这类内部转译，平均 CoT 略短但**偶尔出现一两条特别长的转译样本**。

这是**同一套机制在更早阶段的体现**，但看的指标是"`</think>`闭合"而不是"`答案：N。`完整"。

- **mt=20**：c2c 在 modern 输入上有那批"偷懒短"样本（CoT 17 字左右就 `</think>`），9/40 能挤过 20 token；classical 输入分布集中在 22+，几乎全部 just-missed，只有 2/40 闭合。**modern 双峰里的短峰救场**。
- **mt=24**：4 个额外 token 让 classical 那批集中在 22-26 字符的样本几乎全闭合（31/40），modern 因为长尾里"复制送给小红"的样本（CoT 22-31 字符）还有几条没闭合（30/40）。**classical 集中分布的优势开始显现**。
- **mt=28** 起两边都 40/40 闭合，差距完全转移到"`答案：N。`是否完整"这一层。

## 统一图景

所以你看到的"先 modern 占优 → 短暂 classical 反超 → 全部到 100%"这条曲线，是**截断阈值从分布的左峰扫到右峰**的过程，每次扫过都对应 ±1~5 个样本的越界，看起来像"白话/文言交替占优"，实际是同一分布关系在不同 token 预算下的两面。

## 写课设报告的注意

这些 ±1~5 样本的"占优反转"**不是稳定的语言风格效应**，不应作为"白话更强"或"文言更强"的论据。真正稳定、可写进报告的发现是：

1. **c2c 整体比 m2m 早 ~4-8 个 token 达到稳定**（c2c mt=36 已 100%，m2m 到 mt=44 才 86%）—— 这才是文言路线 + 紧凑 CoT 的真实优势。
2. **m2m 永远卡在 ~85%**：是 `gram_` family 的 modern_think 模板太长（"先换成"+"再减去"+"所以还剩"），与文言/白话对照无关，是数据生成器的模板问题。
3. **边界附近的 view 差异是分布形状的体现**，建议在报告里把"按 view 拆"那两张表的边界档（mt=20/24/28/32/44）合并报告区间值，或者直接只展示稳定区间（mt≤16 全 0；mt=36-44 看稳定值）。

**设定**：6 个 LoRA + baseline × 5 档 max_tokens（32/64/96/128/160）× 2 种题面（白话/文言），测试集是 GSM 1K 的中文化版本（496 题，比 s800 难得多）。

6 个 LoRA 命名规则是"输入 → CoT 风格"：
- m2m / m2s / m2c：白话输入 → 白话 / 结构化 / 文言 CoT
- c2m / c2s / c2c：文言输入 → 白话 / 结构化 / 文言 CoT

## 实验现象（按重要性排序）

### A. CoT 风格分三档拉开差距（最显著的信号）

`mt=160` 白话题面答案准确率：

**结构化 CoT 路线整体最优、文言 CoT 路线整体最差**，且这个排序在 mt=64 起就稳定建立 —— 不是数据噪声，是真实的"CoT 风格决定模型解题天花板"。

### B. 输出端风格的影响 >> 输入端风格的影响

- **同 CoT 路线，跨输入**：m2m vs c2m（都白话 CoT）只差 2pp；c2s vs m2s 几乎平手 → 输入端文言/白话对模型影响很小。
- **同输入，跨 CoT 路线**：m2m vs m2s vs m2c → **40.32% → 44.76% → 14.52%**，跨度 30pp。
- 结论：**真正决定模型能力的不是题面语言，而是 CoT 的语言/形式**。

### C. m2c 是异常 outlier

m2c（白话题→文言 CoT）所有窗口都卡在 13-15%，**不分输入风格**。这是 6 个组合里**最不自然的配对**：模型被强行要求把白话理解的内容用文言 CoT 翻译出来，相当于在推理中间插一道"中→古汉语"的翻译步骤，把 token 预算和注意力都浪费在词面转译上。

### D. c2c 反直觉：白话输入反而比文言输入好得多

c2c 是文言→文言 CoT，按理文言输入是 in-distribution。但实测 mt=160：
- 白话输入：**29.84%**
- 文言输入：**10.48%**

落差 ~20pp。说明 GSM 这种多步应用题被文言化后，**题面本身的语义信息丢失**（虚词遮蔽了关键数量关系），即使模型能写文言 CoT，也理解不到原题的逻辑。

### E. 完整率 ≠ 答案准确率（剪刀差）

`mt=160` 时几乎所有模型整体回答完整率都到 90%+，但答案准确率最高 44.76% → **65pp 的剪刀差**。

对比之前 s800（一步运算）的情形，那里完整率上来后准确率立刻顶到 100%。**GSM 把瓶颈从"能不能写完"换成了"算不算对"**，token 预算不再是限制因素（structured 组在 mt=128 就饱和到 35%，再加 token 也上不去）。

### F. 文言题面普降 10-20pp 答案准确率（但不降完整率）

所有模型在文言题面上的准确率都比白话题面低 10-20pp，**但完整率两边几乎一致**。说明文言增加的是"语义理解难度"，不是"输出生成难度"。modern_question 的逻辑关系比 classical_question 显式得多。

### G. m2m 在 mt=160 文言题上还有 16pp 的"写不完"

m2m mt=160：白话整体回答完整率 95.56%，文言 79.44%。**只有 m2m 有这个不对称**，其他模型两边都 90%+。

这暗示 m2m 是 6 个里"扩展性最差"的：训练时只见过白话输入，遇到文言输入会用更多 token 复述/转译，导致部分样本仍被截断在 160 token 之前。换句话说，**m2m 是 6 个里最"窄"的 LoRA**。

### H. baseline 几乎全 0%

Qwen3.5-0.8B 在没有任何 LoRA 时，对 GSM 中文题答案准确率 0.00%，完整率 0.00%。LoRA 在这个尺度的模型上贡献是**从 0 起步**，不是锦上添花。

**pp = percentage points（百分点）**，是描述两个百分比之间**绝对差值**的单位。

举例区分一下，避免和"百分比"混淆：

- m2m 答案准确率 40.32%，m2c 答案准确率 14.52%
- 两者的差距用"百分点"表示是：40.32% − 14.52% = **25.8 pp**（差不多 30 pp）
- 如果换成"百分比"表达：m2c 是 m2m 的 14.52/40.32 ≈ 36%，或者说 m2c 比 m2m **低了约 64%**

所以：
- **百分点（pp / percentage point）** = 两个百分比的**直接相减**
- **百分比（% / percent）** = 相对比例的变化

在分析评测指标时统一用 pp，可以避免"准确率从 20% 涨到 40% 是涨了 100% 还是 20%"这种歧义。

如果你觉得 PPT 上"pp"对评委不够直观，可以替换成"个百分点"，比如改成"差距约 30 个百分点"，意思一样且更口语化。
