## Headroom 是什么

**Headroom** 是一个 **AI 代理上下文压缩中间件**，核心作用是：在工具输出、日志、文件内容、对话历史"喂给 LLM"之前，先把它们压缩掉 60–95% 的 token，但尽量保留答案所需的信息。

换句话说，它就是一个"token 节流阀"，夹在你的代理调用链和 LLM 之间。

它支持多种压缩策略：
- JSON 结构化压缩
- AST 代码语法树压缩
- 小模型文本摘要压缩

## MCP Server 是什么

**MCP = Model Context Protocol**，是 Anthropic 推出的一个开放标准协议，用来解决一个问题：**怎么让 LLM 统一地调用外部工具/数据源**。

### 类比理解

可以把它类比成 **USB 接口**：

- 以前每个设备（工具）都要单独写驱动（集成代码）
- 有了 USB 标准之后，任何设备插上去就能用
- MCP 对 LLM 做的是同样的事：定义了一套标准接口，LLM 只要"认识" MCP 协议，就能调用任何按这个协议实现的工具

### 具体结构

### MCP Server 做什么

一个 MCP Server 本质上是一个**本地或远程进程**，它：

1. 声明自己提供哪些"工具"（tool list）
2. 监听 LLM 发来的调用请求
3. 执行对应操作，把结果返回给 LLM

比如 Claude Code 本身就内置了一堆 MCP 工具（`Read`、`Edit`、`Bash`、`Grep` 等），你在对话里看到的那些工具调用，底层就是 MCP。

### Headroom 作为 MCP Server 的含义

Headroom 把自己注册为一个 MCP Server，Claude Code 每次拿到工具输出（比如读了一个大文件）后，不直接把原始内容塞进上下文，而是先调用 Headroom 的压缩工具压一遍，再把压缩后的结果塞进去。这个过程对你完全透明。

---

简单说：**MCP Server = 给 LLM 用的标准化插件接口**，任何人都可以按这个协议写自己的"插件"，接入任何支持 MCP 的 AI 工具。

结果是**反压缩**——内容反而变大了。这说明我们的测试方式用错了。

**headroom `compress()` 的实际设计对象是多轮对话历史，不是单条大消息**。它做的是：在一个长对话里，把早期的旧轮次（已经不需要逐字保留的内容）压缩掉，让近期上下文腾出空间。把整个 3.4 MB JSON 塞进一条 user 消息，没有"可以压掉的旧轮次"，headroom 只能加上 CCR 标记 overhead，反而更大。
