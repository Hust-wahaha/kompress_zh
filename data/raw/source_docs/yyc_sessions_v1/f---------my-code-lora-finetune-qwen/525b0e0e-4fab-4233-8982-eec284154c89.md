## 1. "混合 test" 是什么

是我的用词。指默认评测集 [data/final/test_s800_think.jsonl](data/final/test_s800_think.jsonl) —— 这一份文件里**同时包含两种输入视角**的样本：

- 40 条 `view='modern'`（白话题面）
- 40 条 `view='classical'`（文言题面）
- 共 80 条

每条记录有个 `view` 字段标明来源。`eval_five_metrics.py` 的 [compute_metrics()](scripts/eval_five_metrics.py#L173) 会按这个字段自动做 by_view 分桶，输出里能看到 modern 桶 / classical 桶**各自**的准确率。

跟它相对的概念是"单视角 test"：[data/pairings/test_s800_m2m.jsonl](data/pairings/test_s800_m2m.jsonl) 只装白话题面那 40 条，[test_s800_c2m.jsonl](data/pairings/test_s800_c2m.jsonl) 只装文言题面那 40 条。

**为什么先在混合 test 上跑**：一次性能看出"m2m 模型在文言题面上掉多少"、"c2m 模型在白话题面上掉多少"——这就是跨视角泛化能力。如果分两次单视角跑，需要事后人工拼表。

## 2. `--include-baseline` 是什么

看 [eval_five_metrics.py:393](scripts/eval_five_metrics.py#L393)：这个开关会自动追加一条 `baseline:none:none` 的 model spec，等价于多跑一组**不挂任何 LoRA adapter** 的原始 Qwen3.5-0.8B（`build_engine(adapter=None)` 时跳过 `PeftModel.from_pretrained`）。

它和你的 m2m / c2m 走完全一样的 test 集、完全一样的 `max_tokens` 列表、完全一样的指标。最终 `summary.json` 里就会同时有三行：

**为什么要它**：单独看 "m2m 准确率 92%" 没有意义——baseline 可能已经 88%，那 LoRA 只贡献 +4pt；也可能 baseline 只有 30%，那 LoRA 贡献 +62pt。报告里说"微调提升了 X 个点"必须有 baseline 做参照。代价就是评测时间多一份。

按经验，**第一次跑评测一定要带上**，后续重复评测（比如调 `max_tokens`）想省时间可以去掉。
