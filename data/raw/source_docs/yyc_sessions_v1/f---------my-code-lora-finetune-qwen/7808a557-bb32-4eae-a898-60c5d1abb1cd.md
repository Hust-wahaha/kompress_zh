## 怎么看这几个指标（从最重要到次要）

**1. eval_loss（验证集损失）—— 最该盯的一个**

这是「模型在没见过的题上预测得多准」的代理指标。健康的微调长这样：一路下降，然后**平缓收敛、不反弹**。

你这 6 个 run 全是教科书式的健康曲线：第 25 步 → 第 50 步 → 第 56 步，eval_loss 单调下降且后两次几乎贴平（比如 m2m 0.575→0.574）。**没有任何一个出现「先降后升」**——那种反弹才是过拟合的信号。说明 1 epoch 对这个数据量刚好，没训过头。

**2. train_loss vs eval_loss 的关系 —— 判断过拟合/欠拟合**

- 两者都在降、且数值接近 → 健康（你全部满足，比如 m2m 末train 0.588 / eval 0.574，eval 甚至略低，完全没有过拟合）。
- train 一直降但 eval 早早反弹、差距越拉越大 → **过拟合**（背答案了）。
- 两者都降不动、停在高位 → **欠拟合**（没学会，可能 lr 太小/步数不够/任务太难）。

**3. eval_token_acc（验证集 token 准确率）—— 看绝对水平**

注意它衡量的是「逐 token 预测对没对」，**不等于最终答案对错**（真正的题目正确率要靠你的 `eval_compare_full.py` 抽 `答案：N` 来算）。但它能横向对比任务难度：

- m2s / c2s（输出短答案 s）acc 最高（0.88/0.87），因为输出短、套路固定，好学。
- m2c / c2c（输出文言 c）acc 最低（0.72/0.75）、loss 最高、grad_norm 也最大——**文言输出本身就难学**，这不是「训坏了」，是任务难度差异，符合预期。

**4. grad_norm（梯度范数）—— 看训练稳不稳**

理想是「初期略高，随训练平稳下降并趋稳」，没有突然飙到几十/几百或 NaN。你这批最大也就 2.9（m2c 开局），末期都收到 1.5~2.9 之间，**非常稳**，没有梯度爆炸。

**5. learning_rate 曲线 —— 确认调度器按计划走**

日志里能看到 lr 先 warmup 冲到 ~1e-4，再 cosine 衰减到接近 0（末步 8.8e-8）。这正是想要的形状：开头别太猛，结尾收得干净。

## 主流判断「微调不错」的技巧（口诀）

1. **eval_loss 平滑下降后收敛、不反弹** —— 最核心。
2. **train/eval loss 缺口小** —— 不过拟合。
3. **grad_norm 全程有界、无 NaN/spike** —— 训练稳定。
4. **存最优 checkpoint 而非最后一个**：你现在 `best_model_checkpoint=null`，没开 `load_best_model_at_end`。1 epoch 末步刚好是最优所以无所谓，但跑多 epoch 时强烈建议开，自动按 eval_loss 选最好的那个 checkpoint。
5. **多 eval 点**：你 56 步只 eval 了 3 次（step 25/50/56）。点太少看不清曲线形状，多 epoch 时把 `eval_steps` 调密一点更易判断拐点。
6. **最终拿任务指标验收**：loss/acc 都只是代理，**真·成败看下游正确率**——务必用 `eval_compare_full.py` 跑 baseline vs finetuned 的实际答案正确率，那才是结论。
