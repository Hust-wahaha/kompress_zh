## 根本原因

`kompress_zh/.claude/settings.json` 里有两件事同时在起作用：

**第一：`env.ANTHROPIC_BASE_URL` 把这个项目的所有 API 请求硬绑到本地代理**

VSCode 扩展读到这个配置后，不管 Headroom 有没有在跑，都会把请求发到 `127.0.0.1:8787`。代理不在 → 502。

**第二：hooks 试图自动确保代理在运行**

这本来是为了"每次会话/工具调用前自动把代理拉起来"，但实测失败了（截图里 `did not become ready` / `is stale`），所以 hooks 没救到它，502 还是发生。

**为什么你"从没手动在 kompress_zh 下运行 headroom"但它还是有这个配置？**  
Headroom 的 marketplace 插件（`enabledPlugins` 里的 `headroom@headroom-marketplace`）在你通过 VSCode 扩展启用它的时候，会自动往当前项目的 `settings.json` 写入 hooks 和 `ANTHROPIC_BASE_URL`。你当时可能只是在 VSCode 里点了"启用插件"，Headroom 就自动完成了这个配置。

**为什么关 `lora-finetune-qwen` 的 Headroom 终端会影响 `kompress_zh`？**  
两个项目共用同一个代理进程（端口 8787 只有一个）。关掉那个终端，代理死了，`kompress_zh` 的硬绑就断了。`lora-finetune-qwen` 没事是因为它的 `settings.json` 里根本没有 `ANTHROPIC_BASE_URL`，VSCode 扩展直连 Anthropic。
