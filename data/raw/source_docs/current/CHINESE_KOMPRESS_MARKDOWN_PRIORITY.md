# Markdown 原料优先级补充说明

## 结论

在中文 Kompress 数据构造中，`Markdown` 不应被视为普通文档类型，而应视为 **最高优先级原料类型**。

## 为什么 Markdown 重要

真实 Agent / 泛代码工具工作流里，大量“非代码但高价值”的中文文本都会落在 `.md` 文件中，例如：

- `README.md`
- 任务说明
- 需求文档
- 设计文档
- 实验记录
- benchmark 分析
- 周报、同步记录
- 交付说明

这些文本具备几个共同特点：

- 中文占比高
- 自然语言冗余多
- 关键约束混在长段落中
- 常夹杂少量代码块、命令、路径、表格

这正是中文 Kompress 最应该处理的典型场景。

## 对数据构造的直接要求

第一版数据集建议：

- 至少 `40%~60%` 样本来自 `Markdown` 原料
- 优先采集：
  - `README / 项目说明`
  - `任务拆解 / 需求文档`
  - `实验记录 / benchmark 分析`
  - `同步文档 / 周报`
  - `交付文档 / 汇报材料`

## Markdown 抽样规则

优先保留：

- 标题
- 正文段落
- 列表项
- 表格中的自然语言单元格文本

优先剔除：

- 代码块
- 命令块
- 大段日志引用
- 纯路径或纯配置清单

特殊处理：

- 路径、库名、接口名即使混在正文中，也应视作关键信息候选
- 表格可先展开成自然语言片段，再进入压缩标注流程

## 对项目定位的意义

这进一步说明：

我们要做的不是“中文代码压缩器”，而是 **中文 Agent 自然语言上下文压缩器**；而 `Markdown` 正是这种上下文最集中的主要载体。
