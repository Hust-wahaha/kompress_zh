# DeepSeek V4 Pro Teacher Prompt

本文档固定当前第一版 teacher 标注 prompt，用于为中文 plain-text 压缩改写任务生成：

- `compressed_text`
- `style_tag`
- `contains_anchor`
- `quality_notes`

当前结论：

- 已对 `conservative / balanced / aggressive` 三版 prompt 做并行实测
- 第一版正式采用 `balanced` 方案
- `contains_anchor` 当前允许由 `DeepSeek V4 Pro` 一并输出
- 后续若发现大规模误判，再决定是否切回本地规则回填

## 1. 适用范围

该 prompt 只用于标注：

- 中文自然语言长段落
- 中文任务说明
- 中文需求与约束
- 中文文档解释
- 中文结果说明
- 中文进度总结
- 中文交付文本
- 混有少量路径、命令、数字、文件名的自然语言块

不用于直接标注：

- 原始代码块
- 原始日志流
- 原始 JSON / YAML / XML
- 原始 diff / patch
- 纯路径清单

## 2. 最终采用的 System Prompt

```text
你是一个严格的中文压缩改写标注助手。

你的唯一任务是：
对输入的中文自然语言长段落做“保真压缩改写”，产出一个更短、仍可直接使用的中文版本。

这不是摘要任务，不是自由润色任务，也不是古文改写任务。

你必须遵守：
1. 忠实保留原意，不得编造原文没有的新事实、结论、要求、限制、步骤或判断。
2. 明显缩短文本，但不能为了压缩率牺牲关键信息。
3. 优先删除冗余表达、重复解释、客套话、口水话、过度展开的背景句。
4. 允许适度重组句子结构，使表达更紧凑。
5. 遇到文件名、路径、命令、参数、URL、API 名、模型名、版本号、数值、时间、约束条件、验收条件、下一步行动项时，应尽量保留。
6. 若原文中存在明确的任务目标、限制条件、交付物、结论、TODO、风险、决策、下一步，优先保留这些信息。
7. 只输出一个 JSON 对象，不得输出任何额外说明、Markdown 标记或注释。

额外要求：
- 输出风格应为现代中文为主、轻结构化、轻文言压缩感。
- 可使用“因、故、若、下一步、须、勿”等轻量压缩表达，但必须保持现代中文可读。
- 需要在保真和压缩率之间取得平衡。

JSON 字段固定为：
{
  "compressed_text": "...",
  "style_tag": "lite_wenyan_structured",
  "contains_anchor": true,
  "quality_notes": "..."
}
```

## 3. 最终采用的 User Prompt

```text
任务：请对下面这段中文文本做“保真压缩改写”。

压缩目标：
- 尽量缩短
- 保留任务目标、约束、结论、TODO、下一步、风险、交付要求
- 尽量保留文件名、路径、命令、参数、URL、模型名、版本号、数值等关键锚点
- 允许轻结构化、轻文言化
- 不得编造原文没有的信息

原文：
{{original_text}}
```

## 4. 输出格式要求

teacher 输出必须是单个 JSON 对象，字段固定为：

```json
{
  "compressed_text": "...",
  "style_tag": "lite_wenyan_structured",
  "contains_anchor": true,
  "quality_notes": "..."
}
```

字段解释：

- `compressed_text`
  - 压缩改写后的目标文本

- `style_tag`
  - 当前固定为 `lite_wenyan_structured`

- `contains_anchor`
  - 由 teacher 判断原文是否包含值得重点保留的工程锚点，如文件名、路径、命令、参数、URL、模型名、数字、版本号等

- `quality_notes`
  - 一句简短中文备注，如：
    - `保留了路径和文件名`
    - `原文以约束条件为主`
    - `下一步行动项较关键`
    - `常规压缩改写`

## 5. 当前风格边界

允许：

- `需`
- `须`
- `勿`
- `仅`
- `留作`
- `不属主任务`

允许但要节制：

- `因`
- `故`
- `若`
- `置于`
- `择`

当前不希望大量出现：

- `悉`
- `其`
- `然`
- `兹`
- `今须分治`
- 明显古文化长句

判断标准很简单：

- 要像高信息密度现代中文
- 不能像故意写古文
- 不能像摘要腔

## 6. 当前已验证结论

当前这版 prompt 的已验证特征：

- 比 `conservative` 更有压缩收益
- 比 `aggressive` 更稳，不容易过度文言化
- 对路径、文件名、命令、模型名等锚点保留较好
- 对任务目标、限制条件、下一步等信息保留较稳

因此，第一版正式数据标注默认采用本 prompt。
