# Dataset V1 Construction Plan

本文档定义中文 plain-text 压缩改写项目的**第一版正式数据方案**。

目标不是一次性做大，而是先做一版：

- 风格稳定
- 覆盖真实 Agent 文本分布
- 包含一定比例长文本
- 可直接进入最小训练与评测

## 1. V1 的目标

第一版数据要回答三个问题：

1. 当前 teacher prompt 能否稳定产出我们要的风格
2. `Qwen/Qwen3.5-0.8B + Swift + LoRA` 能否学到这种压缩改写行为
3. 对更长中文上下文，模型是否仍能保持保真和锚点保留

所以 V1 不应只采“好压的短文本”，必须显式纳入一定比例更长样本。

## 2. 样本来源优先级

V1 优先从以下来源收集：

1. 项目 README / 任务说明 / 计划文档
2. 实验记录 / benchmark 分析 / 进度同步
3. 交付说明 / 结果解释 / 决策记录
4. 中文 session 总结 / Agent 协作文档
5. 含少量路径、命令、参数、文件名的自然语言说明块

当前不优先纳入：

- 纯 API 文档镜像
- 大量自动生成文档
- 以代码块为主的教程
- 纯日志、纯报错、纯配置清单

## 3. 长度分布要求

V1 明确不只做中短块。

建议按原文字符长度分三档：

### A 档：中短块

- `180 ~ 350` 字
- 占比：`35%`
- 作用：先保证 teacher 风格稳定、训练容易收敛

### B 档：标准块

- `350 ~ 700` 字
- 占比：`45%`
- 作用：作为主力分布，最接近常见中文说明段

### C 档：长块

- `700 ~ 1200` 字
- 占比：`20%`
- 作用：覆盖真实部署里更长上下文，避免模型只会压短文

说明：

- 第一版先不要大规模上 `1200+` 超长块
- 但也不能把长文本完全排除
- 长块必须有，不然部署分布会偏

## 4. 样本类型分布建议

V1 可按以下比例采样：

- `任务说明 / 需求约束`：`25%`
- `文档说明 / README / 设计说明`：`25%`
- `实验记录 / benchmark / 结果解释`：`20%`
- `同步 / 总结 / 决策 / 下一步`：`20%`
- `交付说明 / 输出说明`：`10%`

## 5. 锚点密度要求

V1 不要全部是“纯自然语言无锚点”样本。

建议：

- `contains_anchor = true` 的样本占 `40% ~ 60%`
- 其余样本可为普通中文说明块

这里的锚点包括：

- 文件名
- 路径
- 命令
- 参数
- URL
- 模型名
- 版本号
- 数字约束
- 时间条件

## 6. 风格要求

teacher 产出的 `compressed_text` 必须满足：

1. 明显压缩
2. 尽量保真
3. 轻结构化
4. 轻文言压缩感
5. 保持现代中文可读
6. 关键锚点尽量保留

不接受：

- 纯摘要化
- 只删不改导致结构混乱
- 过度古文化
- 为了“高级感”扭曲语序
- 丢失下一步、约束、交付要求

## 7. 第一版规模建议

建议先做两级规模：

### V1-pilot

- `120 ~ 200` 条高质量样本
- 用途：
  - 验证 teacher 风格稳定性
  - 验证 dataset schema
  - 跑最小训练
  - 看模型是否学到压缩风格

### V1-full

- `400 ~ 800` 条样本
- 在 pilot 确认没问题后再扩

## 8. 推荐执行顺序

1. 先收一批真实中文 Markdown / 文档块
2. 用 `scripts/build_dataset.py source-pool` 切出 source pool
3. 按长度档位抽样，保证长文本比例达标
4. 用 `DeepSeek V4 Pro` 按固定 teacher prompt 做标注
5. 人工抽检：
   - 是否保留目标 / 约束 / 下一步
   - 是否过度文言化
   - 是否误删锚点
6. 生成 `train/val/test`
7. 先跑最小训练

## 9. 当前一句话原则

V1 数据集必须像真实中文 Agent 上下文，而不是只像“好压缩的短说明文”。

所以：

- 要有中短块
- 要有标准块
- 要有一部分长块
- 要有一部分带工程锚点的自然语言块

这样训练出来的模型才更接近真实部署使用场景。
