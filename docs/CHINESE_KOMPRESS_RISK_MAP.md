# 中文 Kompress 项目风险图谱

## 1. 结论先说

如果我们现在开始做中文版 Kompress，**最大风险不是“训不出来”，而是“训出来一个看起来能压缩，但真实 Agent 场景一用就掉质量的模型”。**

所以要避免的不是单纯模型失败，而是：

- 压缩率很好
- demo 也能跑
- 但一上真实任务，信息丢失、意图漂移、下游质量下降

这才是最危险的假成功。

## 2. 可提前规避的风险

这些问题主要靠设计与流程就能提前压住。

## 2.1 把任务做成生成式改写

这是第一大坑。

如果一开始让教师模型“自由压缩”“自由改写”，短期可能看起来更顺，但后面会出现：

- 标签难对齐
- 信息保真难评测
- 压缩后容易引入幻觉或省略
- 小模型训练目标不稳定

规避方式：

- 第一版坚持 **严格抽取式压缩**
- 教师输出只能来自原文
- 顺序不变
- 不允许同义改写

## 2.2 训练数据和真实场景脱节

如果我们只拿新闻、摘要、数学题、教辅材料去训，最后模型可能会学到“文本摘要”，学不到“Agent 上下文压缩”。

规避方式：

- 数据源要覆盖真实目标场景
- 优先加入：
  - 用户需求描述
  - 助手规划与解释
  - 报错排查文本
  - issue / PR 讨论
  - 文档说明

## 2.3 中文标签对齐方案一开始就选错

如果第一版直接强依赖中文分词器做人为词级标签，很可能会卡在：

- 分词歧义
- 标注不稳定
- 对齐失败

规避方式：

- 第一版优先用 **字符级对齐**
- 输出再拼成连续片段
- 后续如果验证有必要，再做更高层级抽象

## 2.4 只看压缩率，不看任务保持率

这是最容易制造“好看结果”的地方。  
压缩率高不代表模型有价值。

规避方式：

- 必须同步看：
  - 压缩率
  - 信息保真
  - 下游任务质量
  - 推理速度

## 2.5 一开始就追求大而全

如果第一版就想做：

- 中文 + 英文混合
- code + logs + prose 一起训
- 多路路由统一模型

大概率会让问题失控。

规避方式：

- 第一版只做 **中文 plain text**
- 结构化内容继续复用 Headroom 原压缩器
- 英文文本继续复用原版 `Kompress`

## 3. 必须靠实验验证的风险

这些问题不是靠分析能彻底回答的，必须上实验。

## 3.1 压缩后真实任务质量是否稳定

这是第一核心风险。

压缩模型在离线指标上可能很好，但一进入真实任务就会暴露问题。  
已有研究和综述都指出，压缩方法的效果高度依赖 benchmark 和任务类型，不同方法会表现出不同的输出动态。

必须验证：

- 问答是否掉点
- 多步推理是否掉点
- 编码助手场景是否漏约束
- RAG 场景是否丢证据

## 3.2 中文抽取压缩是否会出现“语义断裂”

按字符/片段抽取的方案虽然最稳，但有一个真实风险：

- 保留片段彼此独立
- 局部看都对
- 拼起来却让下游模型更难读

这在中文里尤其需要实验看。  
如果断裂严重，后面可能要引入更强的 span-level 约束。

## 3.3 小模型是否真的比直接让大模型压缩更划算

这也是必须诚实面对的问题。

如果：

- 教师压缩本身很贵
- 小模型部署成本不低
- 节省下来的 token 又有限

那产品价值就不成立。

必须验证：

- 单次压缩延迟
- 本地 CPU / GPU 推理成本
- 节约的 token 是否足以覆盖额外开销

## 3.4 压缩是否会系统性伤害某些任务

有些任务天然更能容忍压缩，有些任务则非常脆弱。  
已有研究表明，不同压缩方法在不同 benchmark 上的表现差异很大。

高风险任务通常包括：

- 多约束指令遵循
- 多跳推理
- 细粒度数值条件
- 长链代码修改要求

所以我们不能只做平均值汇总，而要看任务分布。

## 4. 当前最可能踩中的三个大坑

如果按我们现在的路线推进，我认为最可能踩中的前三个坑是：

### 4.1 “压得不错，但真实任务掉质量”

这是最大风险，也是最像成功其实失败的情况。

### 4.2 “标签看起来对，但模型学到的是模板化删词”

如果教师标注风格单一、样本过窄，小模型可能学成：

- 固定删口水话
- 固定保留数字和关键词
- 但遇到真实语义依赖时就崩

### 4.3 “中文片段保留下来了，但可读性太差”

这会导致：

- 人看感觉还行
- 小模型压缩率很好
- 但下游 LLM 难以稳定使用

## 5. 我们应该怎么控风险

当前最稳的控风险策略是：

1. 第一版只做中文 plain-text extractive compression
2. 第一版只追求“稳定不明显掉任务质量”
3. 数据优先覆盖真实 Agent 文本，而不是泛摘要语料
4. 评测必须带真实下游任务，不只做离线压缩分数
5. 不追求一步做到中英混合统一模型

## 6. 对当前项目路线的影响

这些风险并不意味着项目不该做，恰恰相反：

- 说明我们当前路线是对的
- 但必须把“研究问题”定义得更收敛

最正确的第一阶段目标不是：

“做一个最强中文压缩器”

而是：

**做一个在中文 Agent 文本上可用、可接入 Headroom、且不会显著伤害下游任务质量的轻量抽取式压缩器。**
