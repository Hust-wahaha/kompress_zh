# Dataset 800 Expansion SOP

本文档定义从当前 `185` 条高质量数据，扩到下一阶段 `800 ~ 1200` 条的执行方案。

目标不是盲目提速，而是：

- 保持数据方向正确
- 把人工复核集中到高风险样本
- 让普通样本逐步进入半自动批量生产

## 1. 当前判断

当前数据量足够：

- 跑通训练/评测链路
- 验证 teacher 风格大体可学
- 发现主要失败模式

当前数据量不够：

- 判断模型能力是否稳定
- 判断某类数据增强是否可靠有效
- 判断模型在长文本和强锚点场景下是否可部署

因此下一阶段目标应为：

- 总量推进到 `800 ~ 1200`
- 继续保留精品路线，但不再对全量样本逐条重度人工复核

## 2. 生产原则

下一阶段遵守三条原则：

1. 脚本只负责筛查、排序、抽样，不替代人工判断。
2. 人工复核优先投入 `P0/P1` 高风险样本。
3. 扩量按批次推进，每一批都要独立评估，不一次性堆满。

## 3. 目标规模与批次

建议按四批推进：

### Batch A

- 目标新增：`150 ~ 200`
- 重点：长文本 + 规约/执行指南 + 任务说明

### Batch B

- 目标新增：`150 ~ 200`
- 重点：强锚点样本
- 尤其是：
  - URL
  - 路径
  - 文件名
  - 命令参数
  - 版本号
  - 数值约束

### Batch C

- 目标新增：`150 ~ 200`
- 重点：实验记录 / benchmark / 结果解释 / 决策记录

### Batch D

- 目标新增：`150 ~ 250`
- 重点：补齐分布短板
- 依据前几批训练和人工评测结果决定补哪一类

总目标：

- 累计总量推进至 `800 ~ 1200`

## 4. 长度与类型分布

下一阶段仍建议维持：

- `short (180~349)`：约 `30%`
- `medium (350~699)`：约 `45%`
- `long (700~1200)`：约 `25%`

其中长文本占比要比 pilot 再高一点，原因是部署场景并不只包含“好压的短说明”。

类型分布建议：

- `任务说明 / 需求约束`：`25%`
- `文档说明 / README / 设计说明`：`25%`
- `实验记录 / benchmark / 结果解释`：`20%`
- `同步 / 决策 / 下一步 / 执行指南`：`20%`
- `交付说明 / 输出说明`：`10%`

## 5. 审核分层

后续每一批 teacher 标注完成后，先运行：

```bash
python scripts/build_review_queue.py \
  --input-file data/raw/<batch>.jsonl \
  --queue-file experiments/review_queues/<batch>_review_queue.jsonl \
  --sample-file experiments/review_queues/<batch>_review_sample.jsonl \
  --summary-file experiments/review_queues/<batch>_review_summary.json
```

该脚本会将样本分为三层：

### `P0`

必须逐条人工细审。

典型特征：

- 长文本
- 压缩过猛
- 严格锚点疑似缺失
- 关键 cue 疑似掉点

### `P1`

需要重点抽检。

建议人工复核比例：

- 至少 `40% ~ 60%`

### `P2`

普通样本池。

建议人工复核比例：

- `10% ~ 20%`

## 6. 什么叫高风险样本

当前高风险样本主要包括：

- 原文 `700+` 字的长文本
- 带 `URL/路径/文件名/命令/参数/数值约束` 的文本
- 压缩率过低的样本
- 原文含“必须/不得/下一步/TODO/交付/验收/风险”等 cue，压缩后疑似弱化的样本

这类样本必须优先给人工复核。

## 7. 人工复核最该看什么

不要平均用力。人工复核只看高价值问题：

1. 任务目标是否还在
2. 约束条件是否还在
3. 下一步 / TODO / 行动项是否还在
4. 文件名 / 路径 / URL / 命令 / 数值是否被误删或改坏
5. 是否为了压缩率而改意
6. 是否过度文言化或显得“假精炼”

## 8. 批次节奏

推荐节奏：

1. 先构建 source pool
2. 标注一批
3. 跑 review queue
4. 人工处理 `P0` 与 `P1`
5. 合并入正式 raw dataset
6. 重建 train/val/test
7. 每累计 `150 ~ 250` 条新增数据，跑一次小训练
8. 每两批做一次人工评测复盘

不要每加几十条就训练一次，也不要等到加完 `800` 条才第一次回头看。

## 9. 评测判断原则

评测时遵守：

- `strict anchor` 比 `soft anchor` 更重要
- 脚本指标只作诊断，不替代人工判断
- 长文本和强锚点 case 必须抽样人工看

如果模型表现出现：

- `strict anchor` 持续下降
- 长文本明显更容易掉点
- 高风险样本人工质检变差

则应优先回滚数据方向，而不是继续盲目扩量。

## 10. 当前一句话执行策略

前期继续摸着石头过河，但从现在开始，人工精力只重点投向高风险样本；普通样本逐步转入“脚本筛查 + 分层抽检”的半自动扩量模式，目标在保持方向正确的前提下，把总量推进到 `800 ~ 1200`。
