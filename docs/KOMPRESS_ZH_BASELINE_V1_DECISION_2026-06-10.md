# Kompress ZH Baseline V1 Decision 2026-06-10

本文档用于正式收口当前第一版 `kompress_zh` baseline 决策。

目标不是继续讨论“还能不能再抠一点”，而是明确：

- 当前这一版是否已经可作为正式 baseline
- 为什么现在不再围绕局部小幅提升继续打转
- 后续主线应该切到什么方向

## 1. 当前 baseline 定义

当前 baseline 固定为：

- project: `kompress_zh`
- base model: `Qwen/Qwen3.5-0.8B`
- method: `Swift + LoRA`
- mode: `language-model-only`
- dataset tag: `standardset_v6_1234`
- dataset size: `1234`
- train run:
  - `20260610_152155_train_standardset_v6_1234_qwen3.5-0.8b_reference_v1`
- eval run:
  - `20260610_160737_eval_standardset_v6_1234_qwen3.5-0.8b_reference_v1_test_eval`
- final checkpoint:
  - `checkpoint-61`

## 2. 为什么这版可以收成 baseline

当前这版已经具备 baseline 应有的几个条件：

1. 数据链路完整
   - 原料扩池、teacher 标注、review queue、final audit、正式 merge 全链路已跑通。

2. 训练链路完整
   - 本地造数与 AutoDL 训练分层明确，首轮正式训练已稳定收敛。

3. 评测链路完整
   - 已有正式 test set、聚合指标、anchor 口径修正、case-level 人工复核。

4. 能力已成立
   - 模型已经学会中文 plain-text 压缩改写，不是“完全不会”的状态。

5. 边界已清楚
   - 优势、短板、适用场景、非适用场景都已有较明确判断。

## 3. 当前 baseline 的客观结论

这版模型的客观定位是：

- 它是一个**可用的第一版中文 plain-text 压缩改写 baseline**
- 它已经可以支撑后续 `headroom_zh` 接入验证
- 它可以作为公开仓库和 HF 首版发布的基础模型叙事
- 它不是最终效果版，也不是“压缩激进度最优版”

当前主要优点：

- 收敛稳定
- 中文输出自然
- `strict anchor` 保留率较强
- 面向文档、任务说明、规范说明、进度总结这类中文文本已有可用性

当前主要短板：

- 相比 teacher reference，压缩偏保守
- 对“本可明显再压”的样本，常表现为稳妥改写而非强压缩
- 局部仍受模板与训练分布的保守倾向影响

## 4. 为什么现在不继续死抠这一版

当前不再围绕这版做高频小修小补，原因不是“没有任何提升空间”，而是：

1. 边际收益已经明显下降
   - 当前剩余问题更像压缩激进度校准，而不是主能力缺失。

2. 小修小补很容易反复摇摆
   - 今天补一点更激进数据，明天修一点 anchor，容易出现来回摆动而不是稳定跃升。

3. 当前更需要沉淀成果而不是继续局部打磨
   - 否则项目会长期停留在“还差一点”的状态，难形成对外可讲清的阶段性成果。

4. 后续真正高杠杆的提升不在这里
   - 更值得投入的是更高标准扩数、更完整版本训练、真实接入验证，而不是反复抠同一版。

## 5. 现在开始的主线切换

从这一刻开始，项目主线默认切为：

1. 固化当前 baseline
2. 整理对外叙事
3. 为 HF 开源做准备
4. 为 `headroom_zh` 接入验证做准备
5. 把后续能力跃升主要押在更高质量、更大规模数据与下一版训练上

换句话说：

- 当前阶段不再追求“把这版 0.8B 再抠出一点点提升”
- 当前阶段转为“把这版 baseline 做成清晰、可信、可复用的第一版成果”

## 6. 后续工作的推荐优先级

### P0

- 固化 baseline 文档、指标、边界与 case 判断
- 清理 README / 状态文档中的旧表述
- 准备 HF model card 所需的基础信息
- 为后续 `headroom_zh` 接入列出最小验证清单

### P1

- 组织 `1k` 标准集生产规范，供协作者继续扩到 `3k ~ 4k`
- 梳理数据来源类型、风格边界、人工抽检规则
- 准备下一版正式训练的数据输入条件

### P2

- 若后续需要继续提升，再启动第二版训练
- 重点不再是局部缝补，而是更完整的数据增量与更清晰的训练目标

## 7. 一句话结论

`kompress_zh` 当前已经有一版成立的 MVP / baseline。

后续默认不再围绕这版做无止境的小幅调优，而是把它作为正式基线，转入沉淀、开源、接入验证与下一阶段扩展。
